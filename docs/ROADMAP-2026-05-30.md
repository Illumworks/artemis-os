## Strategic horizon (no briefs yet — direction-setting)

These are the larger moves the platform is building toward. Not actionable today, but inform every architectural decision.

### Personal-instance distribution

**Goal:** ship Floating Artemis + Operations + Dev Projects as a personal-instance bundle that any Amira employee can run on their own machine. Each instance has its own memory, OKR, agents, signals.

**Implications shaping current work:**
- Every architectural decision evaluated through "does this scale to N instances?"
- Local LLM hybrid (stewardship Tier 2) becomes meaningful at N=10+ employees
- Scope-based privacy (D10) becomes more important; personal scope must be private
- Memory observations must be portable (export/import via MW4 archive UI)

**Likely sequencing:** after Memory Wings completes + Stewardship lands. Maybe 3-4 months out.

### Salesforce + ChurnZero + Gong integration

**Goal:** bridge Sales and Marketing via the same agent OS. Qualified signals become tracked accounts. Account activity flows back as memory. Shared view of each opportunity.

**Implications shaping current work:**
- **D6 multi-scope observations** (just shipped in MW1) was driven by this — Salesforce records need to belong to district + campaign + account + person scopes simultaneously
- New scope kinds need to be added: `account:`, `person:`, `district:`, `campaign:`
- Carryover writes (MC stream) extend to Salesforce/CRM approval events

**Likely sequencing:** after Memory Wings + Carryover stream completes. Maybe 4-6 months out. Requires Sales team scoping conversation.

### OKR Studio expansion

**Goal:** OKR Studio scope expands from personal → marketing team → company.

**Status:** personal scope working today (4 objectives, 20 KRs, 30 activity rows tracked).

**Implications:** scope hierarchy (D10) supports this without schema change; new scope kinds `team:` and `org:` would surface naturally.

### Hardware: Mac Studio (deferred)

**Direction:** Mac Studio justified across multiple workloads — faster Xcode compile, video/audio, larger LLM hosting, faster project switching. Not specifically for any one feature.

**Implications for current work:** design with hybrid local+cloud in mind even though hardware isn't here yet. SH5 (local LLM adapter) is architected to swap in cleanly when ready.

## Build philosophy (load-bearing)

These principles govern every brief. From `docs/ARTEMIS-OS-MASTER-PLAN.md` + this session's accumulated discipline:

1. **Conversation > forms** — Builder pattern is the front door for meta-objects (agents, skills, workflows, automations)
2. **Self-improvement is structural** — every agent ships with trajectory summarizer; runs produce summaries; Builder reads them to propose
3. **Memory is lossless by structure** — no deletes; supersession only; evidence chains preserved
4. **Subscription-only by default** — Claude Code subscription path for autonomous runtime; API per-token only for interactive surfaces if absolutely needed
5. **Agents propose, humans dispose** — no agent commits without operator approval through a UI
6. **Hallucinations cannot happen** (Jon, 2026-05-29) — Pydantic at every JSON emit site, self-teaching tool errors, grounding tools before proposing
7. **Verify runtime + DB row count + end-to-end loop before declaring shipped** — "substrate complete" is never sufficient. Workers' reports are claims; spot-check critical ones.
