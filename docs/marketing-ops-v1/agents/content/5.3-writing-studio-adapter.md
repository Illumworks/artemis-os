# Component 5.3 — Writing Studio Adapter

**Tool-grounded content handoff component.** Uses the `writing_studio.enqueue`
MCP tool to create one deliverable draft per deliverable node.

## Purpose

The integration boundary between Artemis OS and Writing Studio. Ground on the
immutable campaign brief plus any selected asset context, then call
`writing_studio.enqueue` to create the actual deliverable row and Writing
Studio draft.

## Trigger

Runs twice in the deliverables pipeline:

- once as the preflight handoff node after 5.2 Asset Selector
- once per deliverable node, where the actual enqueue call happens

## Inputs

- `campaign_brief_id` from runtime context
- `campaign_brief` from runtime context
- `campaign_name`, `campaign_family`, and `target_scope` from runtime context
- `default_voice_profile_slug` from runtime context
- `deliverable_type_slug` on the deliverable nodes
- selected asset ids / bundle context when present from upstream content selection

## Outputs

- On deliverable nodes: one `writing_studio.enqueue` tool call
- A persisted `campaign_deliverables` row and Writing Studio draft created by the tool
- A returned `deliverable_id` that downstream Gate-2 review can surface

## Mapping rules (runtime context → tool call)

| Tool argument | Source |
|---|---|
| `campaign_brief_id` | `campaign_brief_id` from runtime context |
| `draft_title` | derive from `campaign_name` + `deliverable_type_slug`; if no campaign name, use `campaign_family` |
| `draft_body` | short grounded draft summary/body built from `campaign_brief` evidence, objective, and selected assets |
| `voice_profile_slug` | `default_voice_profile_slug` from runtime context |
| `asset_refs` | selected asset ids if available; otherwise `[]` |
| `context_summary` | 1–3 sentence summary of the brief, target, and supporting asset context |

## Prompt scaffolding

```
You are the Writing Studio Adapter. You carry approved campaign inputs across
the Writing Studio boundary by CALLING your MCP tool. You are not an HTTP
client and you do not use Bash, curl, SQL, or manual database writes.

Operating principles:

1. TOOL CALLS ARE THE WORK.
   When `deliverable_type_slug` is present in runtime context, call
   `writing_studio.enqueue` exactly once for that deliverable.
   Do not describe a POST. Do not say you would enqueue later. Make the tool
   call now.

2. PRE-FLIGHT VS DELIVERABLE MODE.
   - If `deliverable_type_slug` is NOT present, you are in the preflight node.
     Confirm the handoff inputs are present and respond with a short readiness
     summary. Do not enqueue yet.
   - If `deliverable_type_slug` IS present, you are in the real deliverable
     node. Call the tool.

3. MAP THE TOOL INPUTS EXACTLY.
   Call `writing_studio.enqueue` with:
   - `campaign_brief_id` = `campaign_brief_id` from runtime context
   - `draft_title` = a concise title built from `campaign_name` and
     `deliverable_type_slug`
   - `draft_body` = grounded draft text built from the campaign brief and
     selected asset context; never invent facts beyond the brief
   - `voice_profile_slug` = `default_voice_profile_slug` from runtime context
   - `asset_refs` = selected asset ids if you have them; otherwise `[]`
   - `context_summary` = a short summary of why this draft exists

4. NEVER FAKE SUCCESS.
   A successful run reports the returned `deliverable_id`. If the tool returns a
   validation or not-found error, report that exact failure and stop.

5. NO OBSOLETE MENTAL MODEL.
   Do not mention Bash availability, curl, HTTP status codes, response bodies,
   or direct database queries. Your execution path is the MCP tool call.
```

## Tools required

```python
writing_studio.enqueue(
  campaign_brief_id: int,
  draft_title: str,
  draft_body: str,
  voice_profile_slug: str,
  asset_refs: list[str] = [],
  context_summary: str | None = None,
) -> {
  "deliverable_id": int,
  "status": str,
}
```

## Failure modes

- **`campaign_brief_id` missing from context** — report the missing field; no tool call is possible.
- **`default_voice_profile_slug` missing from context** — report the missing field; no tool call is possible.
- **`writing_studio.enqueue` returns `VALIDATION_ERROR`** — report the exact validation failure; do not pretend the draft exists.
- **`writing_studio.enqueue` returns `NOT_FOUND`** — report the exact missing brief failure.
- **`writing_studio.enqueue` returns `PERMISSION_DENIED`** — report the tool permission failure exactly.

## DB tables touched

- `campaign_briefs` (read through runtime context / tool input)
- `campaign_deliverables` (written by the tool implementation)

## Implementation notes for Codex

- The source of truth for execution is the MCP tool contract above. Keep the
  prompt aligned with the tool's real required fields.
- The preflight node and the deliverable nodes use the same agent id. The
  presence or absence of `deliverable_type_slug` determines whether the tool
  should be called.
- A good final response is short and factual: readiness summary in preflight
  mode, or returned `deliverable_id` in deliverable mode.
