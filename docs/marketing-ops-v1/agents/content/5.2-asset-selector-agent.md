# Agent 5.2 — Asset Selector Agent

LLM-driven asset selection. Picks ONE asset bundle for the whole campaign — all Writing Studio invocations reference the same bundle.

## Purpose

Select the single best asset bundle (primary + up to 3 supporting) for a campaign, given the campaign brief and the Content Registry.

## Why one bundle per campaign (not per deliverable)

If each deliverable (email, social, long-form) picked its own assets independently, an email might reference a different case study than the landing page. The campaign would feel incoherent. By selecting once at the campaign level, every deliverable references the same evidence base.

## Trigger

Fires after 5.1 Campaign Brief Assembler completes successfully. Synchronous.

## Inputs

- `campaign_workspaces.campaign_brief` (just written by 5.1)
- Content Registry — v1: stubbed JSON file at `rulesets/content_registry_stub.json` (see `schemas/asset-bundle.md` v1 simplification note)
  - `// TODO: integrate real Content Registry when Marketing rebuilds it`

## Outputs

- `campaign_workspaces.asset_bundle` (JSONB) — full bundle per `schemas/asset-bundle.md`

## Scoring formula

For each candidate asset, compute:

```
score =
    0.50 * campaign_type_match
  + 0.25 * tag_overlap
  + 0.15 * recent_freshness_bonus
  + 0.10 * use_case_match_llm
```

Where:
- `campaign_type_match`: 1.0 if asset's `campaign_types` contains the campaign's primary `campaign_type`; 0.5 if contains a secondary; 0 otherwise.
- `tag_overlap`: Jaccard similarity between asset's `tags` and the campaign brief's `reason_codes` (mapped to tag-style strings).
- `recent_freshness_bonus`: linear decay 1.0 → 0 over 24 months from `freshness_date`. Anything older than 24 months: 0.
- `use_case_match_llm`: 0–1 from a single LLM call evaluating "Does this asset's content match the specific evidence in this campaign brief?" — see prompt below.

Primary asset = highest-scoring approved asset. Supporting = next 1–3 assets above score 0.5, deduplicated by topic (no two assets covering the same theme).

## Prompt scaffolding (for use_case_match_llm)

```
You are scoring one asset's relevance to one campaign brief.

You score from 0.0 to 1.0 with two decimal places.

CAMPAIGN BRIEF EVIDENCE:
{{campaign_brief.originating_signal.verbatim_snippet}}

CAMPAIGN TYPE: {{campaign_brief.campaign_type}}

REASON CODES: {{campaign_brief.reason_codes | map(attribute='code') | list}}

ASSET:
  Title: {{asset.title}}
  Format: {{asset.format}}
  Description: {{asset.description}}
  Tags: {{asset.tags}}

DOES THIS ASSET'S CONTENT DIRECTLY ADDRESS THE EVIDENCE IN THIS CAMPAIGN?

Score 1.0 if the asset specifically addresses the evidence (e.g., asset is "OBC
performance guarantees" and campaign evidence is RFP demanding measurable growth).
Score 0.5 if the asset is topically related but generic (e.g., asset is "Amira
overview" for any OBC campaign).
Score 0.0 if the asset is unrelated (e.g., asset is "Family engagement strategies"
for an OBC RFP).

Return JSON only: { "score": 0.00-1.00, "reasoning": "1 short sentence" }
```

## Fallback path

If no asset scores above 0.5:
- Set `fallback_used = true` in the bundle
- Pick the highest-scoring asset regardless of threshold
- Add `supporting: []` (no supporting assets in fallback mode)
- Surface a flag on the workspace so human reviewers know to expect lower-quality drafts

`// JUDGMENT CALL:` Alternative is to fail the workspace (`content_preparation_failed`) and force humans to add a matching asset. For v1, pick the best available with a flag; the Approval Drawer in Writing Studio catches issues.

## Tools required

```python
content_registry.list_approved_assets() -> list[Asset]   # v1: reads from JSON stub

# LLM
claude.complete(prompt, model="claude-sonnet-4") -> str
```

## Failure modes

- **No approved assets in registry** — fail loudly. Operator must seed at least one asset of each campaign type.
- **All assets score below 0.5** — fallback path, flag the workspace.
- **LLM returns invalid JSON** — retry once with stricter prompt. On second failure, default `use_case_match_llm = 0.5` (neutral) for that asset and continue.
- **Content Registry stub file missing** — alert, fail workspace.

## DB tables touched

- `campaign_workspaces` (read + write)

## Implementation notes for Codex

- This agent uses Sonnet for the `use_case_match_llm` scoring. Volume is low (one campaign per workspace, asset count per campaign is typically 5–20 candidates). Cost is justified.
- Parallelize the per-asset LLM calls within a single campaign. 10 candidates concurrently is fine.
- The scoring formula weights (0.50, 0.25, 0.15, 0.10) are tuning constants. Surface them in a `services/asset_selector_config.py` so Josh / Angela can tune without code changes.
- Asset registry stub format (`rulesets/content_registry_stub.json`):
