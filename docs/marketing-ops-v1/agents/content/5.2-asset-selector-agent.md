# Agent 5.2 — Asset Selector Agent

LLM-driven asset selection. Picks ONE asset bundle for the whole campaign — all Writing Studio invocations reference the same bundle.

## Purpose

Select the single best approved asset bundle (primary + up to 3 supporting) for a campaign, grounded on the campaign brief and the Content Registry tool result.

## Why one bundle per campaign (not per deliverable)

If each deliverable (email, social, long-form) picked its own assets independently, an email might reference a different case study than the landing page. The campaign would feel incoherent. By selecting once at the campaign level, every deliverable references the same evidence base.

## Trigger

Fires after 5.1 Campaign Brief Assembler completes successfully. Synchronous.

## Inputs

- `campaign_workspaces.campaign_brief` (just written by 5.1)
- `content_registry.list_approved_assets` tool result

## Outputs

- `campaign_workspaces.asset_bundle` (JSONB) — full bundle per `schemas/asset-bundle.md`

## Selection discipline

Ground the selection on the tool output you actually receive:

- campaign-family fit from the campaign brief / runtime context
- summary relevance to the campaign evidence and objective
- metadata tags or campaign-family hints when present
- freshness when timestamps are available
- bundle coherence: no duplicate theme coverage unless the brief clearly needs it

Primary asset = strongest single fit. Supporting assets = next 1–3 approved assets that add distinct evidence or proof points.

## Prompt scaffolding

```
You are the Asset Selector Agent. Your job is to fetch the approved asset pool
with your MCP tool, then choose one coherent campaign-level asset bundle.

Operating sequence:

1. CALL YOUR TOOL FIRST.
   Call `content_registry.list_approved_assets`.
   - If runtime context includes `campaign_family`, pass
     `{"campaign_family": <campaign_family>}`.
   - Otherwise call it with `{}` and work from the full approved pool.

2. GROUND ON THE TOOL RESULT.
   Select from the returned `assets` array only. Do not invent assets, URLs,
   tags, or summaries, and do not refer to a local JSON file or Bash command.

3. PICK ONE CAMPAIGN-LEVEL BUNDLE.
   Choose:
   - one `primary_asset_id`
   - zero to three `supporting_asset_ids`
   - a short `selection_rationale`
   - `fallback_used = true` only when the tool returns assets but none is a
     strong fit and you still choose the best available approved asset

4. RETURN A STRUCTURED RESULT.
   Return concise JSON with:
   `primary_asset_id`, `supporting_asset_ids`, `selection_rationale`,
   `fallback_used`, and `campaign_family`.

5. FAIL CLEARLY WHEN THE TOOL RETURNS NOTHING.
   If `assets` is empty, say that no approved assets are available. Do not
   claim a bundle was selected.
```

## Fallback path

If no asset scores above 0.5:
- Set `fallback_used = true` in the bundle
- Pick the highest-scoring asset regardless of threshold
- Add `supporting: []` (no supporting assets in fallback mode)
- Surface a flag on the workspace so human reviewers know to expect lower-quality drafts

`// JUDGMENT CALL:` Alternative is to fail the workspace (`content_preparation_failed`) and force humans to add a matching asset. For v1, pick the best available with a flag; the Approval Drawer in Writing Studio catches issues.

## Tools required

```python
content_registry.list_approved_assets(
  campaign_family: str | None = None,
  limit: int = 50,
) -> {
  "assets": [
    {
      "id": int,
      "asset_type": str,
      "status": str,
      "summary": str | null,
      "metadata": dict,
      "created_at": str | null,
      "updated_at": str | null,
    }
  ]
}
```

## Failure modes

- **No approved assets returned by the tool** — fail loudly. Operator must seed at least one approved asset.
- **All assets are weak fits** — fallback path, but say so explicitly with `fallback_used = true`.
- **Tool returns malformed asset data** — ignore malformed rows and explain the limitation in the rationale.

## DB tables touched

- `campaign_workspaces` (read + write)

## Implementation notes for Codex

- The source of truth is the MCP tool result, not a local registry file. If the storage layer changes later, the tool contract stays stable and this prompt should still hold.
- This agent does not save assets itself in v1. Its job is to ground the selection on the approved-asset tool result and return a precise bundle recommendation.
