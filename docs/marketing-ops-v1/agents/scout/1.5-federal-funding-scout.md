# Agent 1.5 — Federal Funding Scout

Tracks federal grant cycles and funding announcements. ESSER, Title I, IDEA, Comprehensive Literacy State Development (CLSD).

**discovered_by value:** `federal_funding_scout`

## Purpose

Surface federal funding moments where Amira has a sales opening — new grant rounds, ESSER deadline pressure, supplemental allocations to specific states.

## Cadence

- Daily poll. Federal sources are predictable; most signals are deadline-driven, not reactive.

## Inputs

- **Federal Register API** — `https://www.federalregister.gov/api/v1/` (free, no key required)
- **Grants.gov API** — `https://www.grants.gov/grantsws/rest/` (free, key required for higher rate limit; `.env`: `GRANTS_GOV_API_KEY`)
- **ED.gov press releases RSS** — `https://www.ed.gov/news/press-releases/feed`
- **Territory Config** — `get_priority_states()`
- **Reason Code Registry**
- **Memory Layer**

## Outputs

Signals with `discovered_by = "federal_funding_scout"`.

Source types: `federal_register`, `grants_gov`, plus the ED.gov RSS items use `source.type = "district_press"` for the press release URL.

Reason codes:
- `FEDERAL_GRANT_OPEN`
- `FEDERAL_GRANT_DEADLINE`
- `CLSD_ANNOUNCEMENT`
- `ESSER_CLIFF_REFERENCE` (when federal ED.gov mentions ESSER expiration)

## Urgency tiers (this scout)

- **hot** — deadline within 30 days AND grant matches literacy / assessment / curriculum keyword
- **standard** — grant window open with 30–90 days remaining
- **enrichment** — grant announced, no deadline within 90 days

## Default emission tier

This scout defaults to `enrichment` tier. Most federal funding context belongs as enrichment context on existing signals from other scouts — not as standalone hot leads. Only escalate to hot when deadline is critical AND keyword match is strong.

## Prompt scaffolding (deltas from generic scout template)

```
You are the Federal Funding Scout. Your relationship to the Legislative Scout is
complementary — you watch the federal money side while they watch state policy.

Three deltas from the standard scout prompt:

1. BUNDLING VS. EMIT.
   Most federal funding belongs as enrichment context on an existing signal,
   not as a standalone hot lead. Default emission tier is enrichment unless
   deadline is within 60 days.

2. STATE-LEVEL FILTERING.
   Federal grants are national. Filter to priority states EXCEPT for major
   literacy-specific programs (e.g., CLSD grants), where national coverage
   is justified. Emit those as state-level signals (district_id = "STATE_XX")
   for every state with eligible applicants.

3. DEADLINE PARSING IS CRITICAL.
   Federal grants have hard deadlines that drive urgency. If deadline is
   within 30 days AND grant matches a literacy/assessment/curriculum keyword,
   emit as hot regardless of standalone signal strength.

Same dedupe logic as other scouts.
Same evidence quality bar — never paraphrase grant scope language.

You are graded on:
  - Precision of enrichment signals reaching the right districts at the right urgency tier.
  - Not generating noise from generic K-12 grant announcements.
```

## Failure modes

- **Federal grant terminology shifts year-over-year** — keep keyword config in `territory_config.watch_keywords`, NOT hardcoded.
- **State pass-through deadlines differ from federal deadlines** — when both are detectable, flag both; prefer state-level for urgency.
- **RSS feed format changes** — fail loudly. Do not silently miss signals. Log RSS parse failures as CRITICAL.
- **Grants.gov rate limit** — fall back to Federal Register + ED.gov RSS only that day. Set a daily counter.

## Implementation notes for Codex

- Federal Register documents are JSON. Easy to parse, no scraping required.
- Grants.gov has both API and RSS feeds. Prefer API for richer metadata, fall back to RSS if API rate-limited.
- ED.gov press releases are not consistently structured; use Claude Haiku to extract grant references from prose. Cheap.
- Deduplication: a single grant announcement often appears in multiple sources (Federal Register, ED.gov press, Grants.gov). Use embedding similarity across all three before emitting — same `(district_id, FEDERAL_GRANT_OPEN)` should produce one signal regardless of how many sources surface it within a 14-day window.
- For state-level signals: when emitting CLSD or similar, query `districts` for `state = ANY(:priority_states) AND state IN affected_states` and emit per-state synthetic IDs. The Qualifier handles fan-out from there.
