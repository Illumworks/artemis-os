# Agent 1.4 — Legislative Scout

Tracks state legislature bills across priority states. Literacy mandates, OBC laws, assessment requirements, curriculum directives.

**discovered_by value:** `legislative_scout`
**Build order:** First scout to build. Validates the entire pattern.

## Purpose

Convert state legislature activity into structured signals. Catch bills at three stages: introduction, chamber passage, enactment.

## Cadence

- Daily poll during legislative sessions (Jan–Jun, varies by state)
- Weekly poll off-session
- Chamber votes trigger immediate emit (event mode)

## Inputs

- **LegiScan API** — `https://api.legiscan.com/?key=...&op=search`
  - Free tier: 30k queries/month
  - Paid tier ~$50/mo if free exceeded
  - `.env` key: `LEGISCAN_API_KEY`
- **Territory Config** — `services.territory_config.get_priority_states()`
- **Reason Code Registry** — read-only lookup
- **Memory Layer** — last-seen bill version per `(district_id, bill_id)`

## Outputs

Signals with `discovered_by = "legislative_scout"`, `source.type = "legiscan"`.

## Reason codes emitted

Sourced at runtime from `decisions/campaign-signal-spec-v1.md` (codes where this scout appears in the "Primary scouts" column). Do not hardcode codes here.

## Urgency tiers (this scout)

- **hot** — bill passed a chamber OR vote scheduled within 30 days
- **standard** — bill introduced, hearings underway
- **enrichment** — bill in committee with no scheduled action

## Prompt scaffolding

```
You are the Legislative Scout. Your job is to turn raw state legislature data
into structured signals about K-12 districts that match Amira's strategic territory.

You produce signals — you do NOT decide whether a campaign should launch.

For each LegiScan result:

1. RESOLVE GEOGRAPHY.
   - If bill is district-specific, match to canonical district_id.
   - If statewide, emit one signal with district_id = "STATE_<two_letter>" (e.g., "STATE_FL").
     The Qualifier may fan out to per-district later via routing rules.
   - If state is not in priority_states, discard. No emission.

2. EXTRACT EVIDENCE.
   - Pull verbatim snippet (1–3 sentences) from bill summary or short title.
   - NEVER paraphrase.
   - If bill text is >2000 characters, extract only the section matching the keyword
     that triggered the search.

3. ASSIGN REASON CODES.
   - Codes MUST be from reason_code_registry.
   - Assign topic-specific codes from the registry:
       POLICY_LIT_MANDATE for bills requiring screening / literacy intervention / dyslexia mandates
         — urgency: hot at PASSED_CHAMBER or ENACTED; standard at INTRODUCED
       POLICY_EDTECH_TIME_LIMIT for bills citing screen-time caps or ed-tech-time reduction
       TX_HB1416_WAIVER for TX HB 1416 tutoring waiver legislation (always hot)
       TX_HB3_DYSLEXIA_COMPLIANCE for TX HB 3 dyslexia reporting requirements (always hot)
   - Do NOT invent codes. If unsure, flag with proposed_new_code.

4. SET URGENCY.
   - hot       — bill passed a chamber OR vote scheduled within 30 days
   - standard  — bill introduced, hearings underway
   - enrichment — bill in committee with no scheduled action

5. DEDUPE.
   - Check memory_layer for prior signals on same bill at same stage.
   - Emit only when bill stage advances (material change) OR 60+ days since last emission.
   - For 0.70–0.92 embedding similarity: call material_change_check.

You are graded on:
  - Signal precision (Josh approval rate at Gate 1)
  - Evidence quality (verbatim snippet survives into outreach)
  - Cost per useful signal

You are NOT graded on volume. A quiet day during session recess is correct behavior.
```

## Failure modes

- **LegiScan rate limit exceeded** — exponential backoff (60s, 5min, 30min). Alert if free tier exhausted; consider paid tier.
- **Bill name doesn't resolve to district** — write to `unresolved_signals` table, do not emit signal.
- **Bill references district by old name (post-merger)** — falls into unresolved queue. Expected behavior; do not over-engineer for this in v1.
- **Bill stage advances faster than dedupe expects** — trust the material-change check. If it misses, that's a tuning problem, not a code problem.

## DB tables touched

- `district_aliases` (read for fuzzy matching)
- `unresolved_signals` (write on resolution failure)
- `reason_code_registry` (read)

## Implementation notes for Codex

- LegiScan returns bill summaries that are typically clean. Use the API's full-text fields where available (`url`, `description`, `title`) before falling back to extracted text.
- LegiScan does not natively classify bills by topic. Do keyword-based pre-filter (`literacy`, `reading`, `dyslexia`, `biliteracy`, `outcomes-based`, `assessment`, `tutoring`, `curriculum`) before sending to LLM for reason code assignment. This cuts LLM cost significantly.
- For state-wide bills, emit ONE signal per state per material change. Do NOT fan out into 50 district signals at scout time — that's the Qualifier's job via routing rules.
- The scout itself uses Claude Haiku for reason code assignment (cheap, high-volume task). Reserve Sonnet for the material-change check (rarer, higher-stakes).
- Pseudocode for the main loop:

```python
def run_scout():
    states = territory_config.get_priority_states()
    for state in states:
        if not is_in_session(state):
            continue  # off-session, skip
        bills = legiscan.search(state, LITERACY_KEYWORDS, last_24h)
        for bill in bills:
            district_id = resolve_district(bill, state)  # may return STATE_XX
            if not contact_db_stub.has_contact(district_id):
                continue
            signal = build_signal(bill, district_id)
            if should_emit_after_dedupe(signal):
                signal_queue.write(signal)
                memory_layer.upsert(...)
```

- `LITERACY_KEYWORDS` is a configurable list, sourced from `territory_config.get_watch_keywords()`. Do NOT hardcode in scout source.
- Run as a scheduled job (APScheduler or cron). One run = one full sweep across all priority states.
