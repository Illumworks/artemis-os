# Agent 1.3 — LinkedIn Observer (Mode B only in v1)

Public LinkedIn observation of education leaders. Two modes in the original design; **Mode A is disabled for v1** (no consumer; Contact team out of scope).

**discovered_by value:** `linkedin_observer`
**v1 scope:** Mode B only.

## Mode A (DISABLED in v1)

**Follower Digest.** Watch Amira's company-page followers, emit enrichment context for the Contact team's enrichment queue. Disabled because the Contact team is out of v1 scope.

Do not build Mode A in v1. The scraper code paths should exist as no-ops so they can be enabled later without re-architecture.

## Mode B (ACTIVE in v1)

**Leader Monitor.** Watch a bounded list of education leaders' public posts. Emit signals when a watched leader posts content matching campaign themes (literacy, dyslexia, OBC, biliteracy, growth, ESSER, curriculum review).

## Purpose

Detect public LinkedIn activity that signals a buying window or topical interest at a watched district. This is **enrichment-tier in most cases** — it reinforces signals from other scouts. Rarely standalone hot.

## Cadence

- Event-driven (post detection via watched-profile polling, hourly during business hours)
- Bounded watch list: ~200–500 profiles (matches district watch list — 1 supe + 1–2 senior leaders per district)

## Inputs

- LinkedIn public profile / post data. **Public reads only.** No automated logins, no scraping behind auth walls.
- For v1: use the Phantombuster / Proxycurl / similar legitimate scraping service. `.env` key: `LINKEDIN_SCRAPER_API_KEY`.
- Watch list: `linkedin_watch_profiles` table (district_id, linkedin_url, role).

## Outputs

Signals with `discovered_by = "linkedin_observer"`, `source.type = "linkedin_post"`.

## Reason codes emitted

Sourced at runtime from `decisions/campaign-signal-spec-v1.md` (codes where this scout appears in the "Primary scouts" column). Do not hardcode codes here.

## Urgency tiers (this scout)

- **enrichment** — default; LinkedIn rarely produces standalone hot signals
- **standard** — when post explicitly references vendor change / curriculum review / RFP
- **hot** — never; LinkedIn alone does not justify hot urgency

## Prompt scaffolding

```
You are the LinkedIn Observer (Mode B). You watch a bounded list of district
leaders' public LinkedIn activity for content that signals a buying window
or topical interest.

You produce ENRICHMENT signals primarily. Your job is to provide context that
strengthens signals from other scouts — not to drive outreach alone.

For each post from a watched profile:

1. CONFIRM the profile is in the linkedin_watch_profiles table and maps to a
   priority district. Otherwise discard.

2. EXTRACT verbatim 1–2 sentence snippet from the post that matches a
   campaign theme keyword. Never paraphrase.

3. ASSIGN REASON CODES.
   - LEADER_TRANSITION_INTERIM when profile shows interim role change
   - LEADER_TRANSITION_FORMAL when a formal hire is announced (flag for 1.9 two-source confirmation before hot)
   - VENDOR_DISSATISFACTION when post names a competitor with negative valence (efficacy, cost, fit, renewal)
   - Any other topical reason code the post content triggers from the registry

4. URGENCY.
   - Default: enrichment.
   - Standard only if post explicitly references vendor change / curriculum
     review / RFP / public selection process.
   - Never hot. LinkedIn alone does not justify hot urgency.

5. CONTACT HINTS.
   - Populate contact_hints with the leader's name + role + profile URL.
   - This is the one place LinkedIn data lands on a signal in v1.

6. DEDUPE.
   - One signal per (profile_id, week). A leader who posts daily about
     literacy generates one signal per week, not seven.

Public reads only. No automated logins. No scraping behind auth walls.
```

## Failure modes

- **LinkedIn API / scraper service rate limits** — back off, do not aggressively retry. LinkedIn enforcement is real.
- **Profile becomes private** — log and remove from watch list. Do NOT keep retrying.
- **Profile changes employer** — picked up by 1.9 Leadership Transition Scout. This scout flags the gap (no longer at watched district) and stops watching.
- **Post is reshared content vs. authored content** — only emit on authored content. Reshares are weak signal.

## DB tables touched

## Implementation notes for Codex

- The `linkedin_watch_profiles` table should be seeded from `districts.superintendent` for watch-list districts. A maintenance job (weekly) keeps it in sync with Leadership Transition Scout updates.
- Use Claude Haiku for post → reason code classification. This is high-volume, low-stakes.
- **Cost containment:** LinkedIn scraping APIs charge per request. Budget alarm at $500/mo; if exceeded, throttle watch list to top 100 profiles only.
- **Legal/ToS note:** LinkedIn's ToS prohibits some forms of automated scraping. Use only services that have established legal precedent for public-data access (e.g., Proxycurl post-hiQ). Mark this with `// LEGAL: confirm scraper service ToS compliance before production deploy.`
