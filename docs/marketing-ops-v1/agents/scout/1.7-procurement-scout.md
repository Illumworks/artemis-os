# Agent 1.7 — Procurement Scout

Tracks RFPs, RFIs, and procurement postings across statewide procurement portals plus per-district portals for the watch list.

**discovered_by value:** `procurement_scout`
**Status:** Net-new capability. RFPs / procurement are not currently a Starbridge use case at Amira.

## Purpose

Surface RFP and procurement signals at the moment they become actionable — before the BDR team would normally discover them through other channels.

## Cadence

- **Statewide portals:** twice-daily poll (RFP windows are short)
- **Watch-list district portals:** daily poll
- **Broader district set:** weekly sweep

## Inputs

- **Statewide procurement portals** — per-state config. Examples:
  - CA eProcurement
  - GA Procurement Registry
  - TX SmartBuy
  - FL Vendor Bid System (VBS)
  - IL BidBuy
  - IN Department of Administration
  - MD eMaryland Marketplace Advantage (eMMA)
  - MI Bid4Michigan
  - MO Office of Administration Procurement
- **Per-district portals** — for watch-list districts: BoardDocs, Granicus, district website procurement pages
- **PDF Extractor service** (for RFP scope documents)
- **Watch list** (`districts.is_watch_list = TRUE`)
- **Optional v2:** BidNet, DemandStar paid APIs (skip in v1)

## Outputs

Signals with `discovered_by = "procurement_scout"`, `source.type = "procurement_portal"`.

## Reason codes emitted

Sourced at runtime from `decisions/campaign-signal-spec-v1.md` (codes where this scout appears in the "Primary scouts" column). Do not hardcode codes here.

## Urgency tiers (this scout)

**All RFP signals are hot.** The variable is intensity by `days_to_close`:

- **hot (critical window)** — `days_to_close ≤ 14` — PROCUREMENT_LITERACY_RFP at highest urgency
- **hot** — `days_to_close 15–45`
- **standard** — `days_to_close > 45` (with deadline tagging)

## Prompt scaffolding (deltas)

```
You are the Procurement Scout. Your signals drive the most direct sales action
of any scout — an RFP signal often means a deal cycle is opening NOW.

Three deltas:

1. TIGHTER RELEVANCE BAR.
   Only emit RFPs that match Amira's product surface — literacy assessment,
   reading intervention, tutoring, curriculum. Reject:
     - general K-12 IT (laptops, networking)
     - transportation
     - food service
     - facilities / construction
     - non-instructional services
     - federal parts / logistics / depot buys, even if SAM keyword matching
       drags in a stray "reading", "literature", or training term
     - DoD / DLA / military maintenance solicitations unless the actual scope
       is plainly K-12 instructional
   When in doubt, lean toward NOT emitting. False positives waste BDR time.
   For SAM.gov specifically, treat education NAICS as a prior (`611110`,
   `611710`, `611310`, `611691`, `624310`) but not as sufficient evidence by
   itself. The title or scope still needs to describe a real school-facing
   literacy / curriculum / assessment / tutoring need.

   Query discipline:
   - Prefer title-focused searches first (`literacy`, `reading assessment`,
     `curriculum`, `tutoring`) with the education NAICS filter attached.
   - Use broader keyword search only as fallback when title search is sparse.
   - A posting is not relevant just because SAM returned it.

2. DEADLINE IS THE URGENCY.
   ALL RFP signals are hot. The variable is how hot:
   - days_to_close ≤ 14: emit PROCUREMENT_LITERACY_RFP as hot (critical window)
   - days_to_close 15–45: emit as hot
   - days_to_close > 45: emit as standard unless strategic district
   Also emit FUNDING_DEADLINE_NEAR when days_to_close ≤ 90 for funding-backed RFPs.

3. INCLUDE SCOPE VERBATIM.
   The evidence.verbatim_snippet for RFPs must include the actual scope language
   so BDRs can decide relevance without opening the source. Aim for 3-5 sentences
   covering: what they want, enrollment served, deadline.

Dedupe per (district_id, rfp_id) — never emit the same RFP twice.
Use the RFP number from the source as part of the fingerprint, not just the URL.
```

## Failure modes

- **RFP posted on portal AND BoardDocs creates duplicate** — fingerprint must include RFP number + district_id, NOT just URL. Two URLs pointing to the same RFP should produce one signal.
- **Statewide portal posts cooperative-bid RFPs covering multiple districts** — emit one signal per affected priority district. Cooperative-bid RFPs typically list participating districts in the scope document; extract and resolve each.
- **Scraper breaks mid-RFP-window** — ALERT IMMEDIATELY. Missed RFPs have real revenue cost. Do not silently retry.
- **PDF scope documents in non-text formats (scanned)** — flag `source_quality_low`. Use the title and short description from the portal as fallback evidence if PDF extraction fails.

## Implementation notes for Codex

- Statewide portals all have different formats. Build one adapter per portal. Adapter files in `artemis_os/scrapers/procurement/<state>.py`.
- District portals are even more varied. For v1, only build adapters for watch-list districts. Adding a new district adapter should be a config + 1–2 hours of scraper code.
- RFP number extraction: most portals have an explicit RFP / Solicitation ID field. Pull this; use it as part of the dedupe fingerprint.
- Days-to-close calculation: parse `due_date` from portal, subtract `discovered_at`. Re-emit as a higher urgency tier if days_to_close drops into the ≤ 14 window — that's a material change.
- For cooperative-bid RFPs: extract participating-district list from the scope PDF. Resolve each to canonical district_id. Emit one signal per district in priority states. Skip the rest.
