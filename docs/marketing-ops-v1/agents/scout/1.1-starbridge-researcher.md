# Agent 1.1 — Starbridge Researcher

Legislation + funding via Starbridge API. Highest-volume scout in the original architecture, produces most "hot" signals.

**discovered_by value:** `starbridge_researcher`
**Status:** **Bench-test for 6–12 months.** Throttled credit usage. Kept active to compare against new internal scouts (1.4–1.9). Decision on renewal / cancellation at end of bench-test.

## Purpose

Convert Starbridge's stream of legislative and funding data into structured, district-attributed signals — same schema as all other scouts.

## Cadence

- Scheduled poll every 4h (configurable)
- Event-driven webhook if Starbridge supports push (TBD with Starbridge API team)

## Inputs

- **Starbridge API** — access pattern TBD with Starbridge team. `.env` key: `STARBRIDGE_API_KEY`
- **Territory Config** + Reason Code Registry (read-only)
- **Memory Layer** — last-seen timestamp + embedding hash per `(district, reason_code)`

## Outputs

Signals with `discovered_by = "starbridge_researcher"`, `source.type = "starbridge"`.

Reason codes: any from registry, scout-determined.

## Urgency tiers (this scout)

- **hot** — RFP deadline ≤ 30 days OR bill passed a chamber
- **standard** — deadline 30–90 days OR ongoing legislation
- **enrichment** — no deadline, background context

starbridge.search(filters: dict) -> list[Item]

# Shared

## Prompt scaffolding

```
You are the Starbridge Researcher. You produce signals — you do NOT decide
whether a campaign should launch.

For each Starbridge result:

1. Resolve geography → canonical district_id. Discard if not in priority_states.
2. Extract verbatim 1–3 sentence evidence snippet. Never paraphrase.
3. Assign reason codes from registry only. Flag proposed_new_code if needed; do not invent.
4. Set urgency tier based on deadline parsing.
5. Dedupe via embedding similarity. >0.92 suppress · <0.70 emit · 0.70–0.92 run material-change check.
6. Emit one signal per district per discrete event.

Graded on signal precision, evidence quality, cost per useful signal. NOT graded on volume.
```

## Failure modes

- Result doesn't map to known district → log to `unresolved_signals`, do not emit.
- Registry missing obvious code → emit with `proposed_new_code` flag.
- Dedupe catches genuine new development → material-change check must catch.
- **Starbridge API outage** → exponential backoff, alert if > 1h. Do NOT fail the build of other scouts; Starbridge is intentionally one source among many.
- **Credit exhaustion** → log clearly; this is a planned constraint during bench-test. Other scouts continue.

## DB tables touched

- `signal_queue`, `memory_layer`, `districts`, `unresolved_signals`, `reason_code_registry`, `territory_config`
