# Agent 2.4 — Brief Composer Agent

Converts a qualified signal (Phase 3 output from 2.1 Cross-Reference Agent) into a Signal Brief — the human-readable card that lands in the Signals Inbox.

## Purpose

Translate a structured `(signal + ruleset_scores + routing)` tuple into the Josh-readable brief that drives Gate 1 review.

## Cadence

Runs immediately after 2.1 Cross-Reference Agent Phase 3 completes on a qualified signal. **Synchronous, in-memory handoff** — not via the signal queue.

## Inputs

- The originating `Signal` object (from `signal_queue`)
- Phase 2 ruleset scores (from Cross-Reference Agent, in-memory)
- Phase 3 routing decision (from Cross-Reference Agent, in-memory)
- `signal_queue` — for `related_history` lookup (prior signals at same district)

## Outputs

A `SignalBrief` row written to `signal_briefs` with `status = 'pending_human_review'`. After write, update the originating signal's status from `qualified` to `brief_composed` → `pending_human_review`.

See `schemas/signal-brief.md` for the full output schema.

## Prompt scaffolding

```
You are the Brief Composer Agent. You take a qualified signal and write the
inbox card Josh and Angela will see at Gate 1.

You do NOT decide whether the signal is worth pursuing — that's Josh's call.
You describe; you do not sell.

Voice rules:
  - Calm, dependable. Never breathless. Never marketing voice.
  - Amira brand terminology required:
      "Learning Agent" not "platform"
      "Dynamic Assessment" not "screener"  (as primary term)
      "Coherence Map" not "Mastery Map"
      "Neuroscience" not "brain science"
      "Assess-Instruct-Tutor" not "Assess-Tutor-Instruct"
  - Never reproduce marketing claims. Just describe what the signal says.

Composition rules:

1. HEADLINE.
   ≤ 80 characters. Format: "District (State) — single most important fact".
   No marketing language. Just the fact.

   Example: "Pinellas County (FL) — Reading Intervention RFP with measurable-growth language"
   NOT:     "Hot Florida Lead! Pinellas County Buying NOW"

2. WHY_FLAGGED.
   1–2 sentences in your own words explaining what made this signal pass and
   why a human should care. Reference the highest-contributing rules from
   the Phase 2 evidence.

   Example: "RFP scope explicitly requires monthly efficacy reporting tied to
   state ELA standards — strong OBC fit signal. Board-vendor-accountability
   rubric also fired (0.85 confidence)."

3. EVIDENCE.
   Verbatim from signal.source.verbatim_snippet. NEVER paraphrase.
   If snippet is longer than ~3 sentences, you may select the most relevant
   sub-quote — but it MUST be an exact substring of the original.

4. FIT_SCORES.
   Primary = top score from Phase 3. Secondaries = any other rulesets > 0.6
   that are NOT redundant with primary (apply redundancy rules from each
   ruleset's routing config).

5. SUGGESTED_CAMPAIGN.
   "<primary>" or "<primary> + <secondary> variant".
   Example: "OBC" or "OBC + general_growth variant".

6. RELATED_HISTORY.
   Max 3 bullets pulled from prior signals at the same district_id (last 12 months).
   Format: "<MM YYYY> — <event in your own words, ≤ 100 chars>"
   Example: "Q4 2025 — Pinellas board discussed vendor accountability"

7. URGENCY.
   Copy from the upstream signal's urgency object. You may override only the
   tier if Phase 2 scoring suggests different urgency than the scout's emission
   — flag with a metadata note in that case.

OUTPUT FORMAT:
  Return JSON only (no preamble, no markdown fence). Match the SignalBrief
  schema exactly. The fields headline, why_flagged, evidence, fit_scores,
  suggested_campaign, related_history, urgency are required.
```

## Tools required

## Failure modes

- **LLM returns invalid JSON** — retry once with stricter prompt. On second failure, write a fallback brief composed deterministically from the signal evidence (no LLM): headline = "{district} ({state}) — {first reason code}", why_flagged = "Auto-composed fallback. See evidence.", evidence = verbatim snippet. Log the failure.
- **No related history for district** — that's fine. Leave `related_history` as empty array.
- **LLM brand-terminology violation** (e.g., uses "platform" instead of "Learning Agent") — for v1 don't auto-correct; flag in metadata for review. Josh / Angela catch at Gate 1. (`// JUDGMENT CALL:` add a deterministic post-pass terminology check later if violations are common.)

## DB tables touched

- `signal_queue` (read + status update)
- `signal_briefs` (write)
- `districts` (read)

## Implementation notes for Codex

- Use Claude Sonnet for this agent. The composition quality matters and per-signal volume is low (signals that reach this point have already passed Phase 1 and 2). Cost is justified.
- Render the system prompt once at startup and reuse — don't rebuild per signal.
- Pre-compute `related_history` deterministically (DB queries) before invoking the LLM. Pass the formatted bullets to the LLM in the prompt; the LLM just selects / wordsmiths from the deterministic input.
- Validate output against `SignalBrief` schema before writing to DB. Reject and retry if validation fails (use Pydantic).
- Pseudocode:

```python
def compose(signal: Signal, phase2: Phase2Result, phase3: Phase3Result) -> None:
    related = compute_related_history(signal.geography.district_id)
    district = districts.get(signal.geography.district_id)
    prompt = render_template(BRIEF_COMPOSER_PROMPT, signal=signal, phase2=phase2, phase3=phase3, related=related, district=district)
    response = claude.complete(prompt, model="claude-sonnet-4")
    brief = parse_and_validate(response)
    signal_briefs.write(brief)
    signal_queue.update_status(signal.signal_id, "brief_composed")
    signal_queue.update_status(signal.signal_id, "pending_human_review")
```
