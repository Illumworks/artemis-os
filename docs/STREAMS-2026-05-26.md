## Rules in force (all streams)

1. **Sequential dependencies are honored.** F1 → F2/F3; F2 → P2. No parallel work on shared files.
2. **No worker self-merges.** Terminal-Lead owns merges to `lead/j6a-granola-integration`.
3. **File ownership per stream.** Each stream's brief names its owned files. Scope creep into other files → stop and ping back.
4. **Self-tests are non-negotiable.** Every brief specifies acceptance assertions the Worker runs themselves.
5. **No remote pushes.** Local-only repo discipline (per `CLAUDE.md`).
6. **Functionality > polish.** Do not polish prose / styling / error messages / log formatting unless functionality requires it.
7. **Hard LOC caps.** If hit, commit what's done, ping back, do not push through.
8. **Browser smoke is Lead's job post-merge.** Workers provide cURL + psql + check.sh evidence. Lead does eyes-on-glass after merge from this Lead session via `preview_*` MCP tools.

```bash
    async with SessionLocal() as s:
        print(await seed_marketing_agents(s)); await s.commit()

"
```

Then re-run the F2 `_build_system_prompt` smoke to confirm the richer blueprints flow into the LLM prompt.

## What to do when a Worker reports back

Jon pastes the report into the Lead chat. Lead does:

1. Verify the report against the brief's acceptance criteria. Each criterion either has paste-evidence or it doesn't.
2. If criteria met: terminal-Lead merges the Worker branch (Jon pastes "merge worker/<name>" if needed). Lead browser-smokes from this session (if UI-touching). Lead updates this doc — status → "merged" with commit hash.
3. If criteria NOT met: Lead drafts a fix-up patch brief (terse, paste-ready) and hands it back to Jon for routing.
4. Lead updates `LEAD-SESSION-LOG.md` decision log with the outcome.

## Conflict-resolution policy

If two streams collide on a file mid-flight (shouldn't happen if rules are honored, but):

1. The earlier-fired stream wins. The later-fired stream stops, ping back to Lead.
2. Lead reconciles by re-issuing the later stream's brief with the merged-state file as the starting point.
3. No "merge it yourself" decisions by Workers.
